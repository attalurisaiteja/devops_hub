pipeline {
    agent any   // Defines where the pipeline runs (any available agent)

    stages {
        stage('Checkout') {
            steps {
                // Pull code from Git repository
                git branch: 'main', url: 'https://github.com/your-org/your-repo.git'
            }
        }

        stage('Build') {
            steps {
                // Compile or build the project
                sh 'mvn clean install'
            }
        }

        stage('Test') {
            steps {
                // Run unit tests
                sh 'mvn test'
            }
        }

        stage('Package') {
            steps {
                // Package the artifact (JAR/WAR)
                sh 'mvn package'
            }
        }

        stage('Deploy') {
            steps {
                // Example: Deploy to AWS EC2, S3, or Kubernetes
                sh './deploy.sh'
            }
        }
    }

    post {
        success {
            echo 'Pipeline executed successfully!'
        }
        failure {
            echo 'Pipeline failed. Sending notifications...'
            // Example: Slack or email notification
        }
    }
}



Pipeline hierarchy   
pipeline               → The main container that defines the entire Jenkins CI/CD workflow
 └── stages            → A collection of logical phases in the pipeline
      └── stage        → A single phase representing one task like build, test, or deploy
           └── steps   ← actual execution happens here
		   
		   




















Job Type: Jenkins Declarative Pipeline
•	Source Control: GitHub repository containing application code and Jenkinsfile
•	Stages:
1.	Checkout → Pull latest code from GitHub.
2.	Build → Compile code and package artifact using Maven.
3.	Test → Run unit tests with SonarQube.
4.	Code Quality → Analyze code with SonarQube.
5.	Deploy → Deploy artifact to staging server Tomcat.
6.	Post Actions → Notify via email/Slack if build fails or succeeds.
